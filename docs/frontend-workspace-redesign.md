# 日常工作台界面重构

日期：2026-11-22。此批次属于已批准的动态本体知识服务工作台重构，先解决日常界面入口过多的问题；本体后端的版本、事实证据与查询内核按原方案后续实施。

## 改造前的界面证据

在隔离数据副本上打开原应用，正常窗口为 1280×720。

1. 首页：可正常加载，但侧栏有二十多个入口且需要滚动。工作区、应用、发现、系统四组同时展开，管理功能与日常阅读并列。下面的截图只能证明当时可见的布局，不能证明辅助技术支持或所有页面的可用性。
2. 首页内容：四张统计卡加三个主入口、七个次入口，再加“我的应用”和“最近活动”，重复提供导航。AI 入口只有图标，而首页的“AI 助手”快捷项实际进入模型设置，难以形成自然的问答流程。

## 参考来源与采用的规则

- [Notion 的侧栏导航](https://www.notion.com/help/navigate-with-the-sidebar)：清晰的主入口、分组、可收起内容和个人快速访问。
- [Linear 的搜索](https://linear.app/docs/search)：按用户任务快速定位内容，提供键盘入口和明确结果。
- [Nielsen Norman Group：渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)：默认展示核心功能，将低频、高级功能收敛为一个清晰的二级入口。

这些来源用于交互原则参考；本次沿用现有 Vue、Element Plus、字体和深靛主色，不是复刻上述产品。

## 产品结构

默认五个主入口：工作台、资料库、知识笔记、知识图谱、业务应用。角色无权限的入口不出现；图谱根据现有页面权限选择可用入口。自定义快捷访问有数量上限，完整列表仍能搜索。

“全部功能”保留模型、关联定义、业务图谱、养料、开发、系统管理等现有功能。快捷搜索与它共用同一个权限过滤目录。减少同时展示的入口，不减少已有能力。

首页优先支持提出问题、导入资料和记录笔记，再展示真实的最近内容与资料。原始记录和深链接保持可访问。资料抽取、审核、事实引用等尚未实施的后端能力不会在此批次伪装成已完成。

## 验收结果

| 步骤 | 状态 | 实测结果 |
|---|---|---|
| 1. 日常首页与导航 | 通过 | 正常窗口 1280×720，五项主入口及一项现有自定义快捷方式；主导航无需滚动 |
| 2. 全部功能与快捷搜索 | 通过 | 完整目录保留 22 个内置目的地；可按名称和旧称搜索，键盘上下键、Enter、Escape 可用 |
| 3. 连续内容搜索 | 通过 | 换词、清空后重复搜索、未提交输入后重复搜索，地址栏与可见输入一致；过期请求被取消并有序号兜底 |
| 4. 首页直接操作 | 通过 | 写笔记直接展开现有编辑器；导入资料定位原生上传按钮；最近文件打开真实文件预览 |
| 5. AI 问题传递 | 通过当前可测范围 | 首页问题传入助手；未配置模型时保留问题并显示状态。未实际调用外部模型，未验证生成答案的质量 |
| 6. 手机与主题 | 通过 | 390×844 下文档宽度为 390，无横向溢出；抽屉可进入功能目录；深色与浅色正常 |
| 7. 权限及受限角色 | 自动检查通过 | 目录/自定义深链接按页面和功能权限过滤；仅笔记权限时单独获取最近笔记，避免混合样本误判为空；未声称做过全部角色的浏览器穷举 |

全部 25 个前端测试脚本通过，生产构建通过，浏览器控制台未出现错误或警告。图表和图谱大分块提示沿用现有情况，本批没有将其作为性能优化项目处理。

独立审查发现并修复：搜索同路由查询不同步、受限角色最近列表误判为空、搜索框聚焦、上传与 AI 设置入口的键盘语义、助手配置缓存失效。

验证使用备份数据副本；没有写入新的业务笔记或上传测试文件。原服务入口为 `http://localhost:8082`；独立正式构建预览为 `http://127.0.0.1:8083`，使用副本数据，不连接原始业务库。开发热更新端口为 5174。
