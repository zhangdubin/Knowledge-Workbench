# 中文知识服务：岗位试点与运行说明

本期把本体基座接到知识查阅工作。采用制度流程、保障参考资料、培训和项目知识作为可配置领域；首批示例仅用于验收副本，不自动装入正式库。

## 岗位怎样使用

在“业务应用 → 知识服务”选择获准知识空间，按业务主题、适用范围和日期查阅。可以输入中文问题、首选术语、别名或文号。命中知识时先看结论状态，再核对适用期及引文；点击出处查看保存的解析快照，也可以单独打开原始文件。

建议先试两个工作闭环：

1. 岗位人员查“维护规程规定的维护记录如何填写？”，选择保障管理范围及当前日期；核对资料版本和已审核依据，再打开逐字引文。日期换为历史时点后，系统重新筛选当时适用资料。
2. 岗位人员发现缺少记录表单，通过当前查询提交“希望补充资料”反馈，取得编号；获准处理人员查看问题、核对原文并填写结论。重复点击或网络重试复用同一幂等标识，保留一条记录。反馈结论不直接改写正式知识。

“有依据”表示找到当前授权、适用且已接受的事实及引文；“存在冲突”保留同一范围内相互不同的依据；“信息不足”不能作为确定结论；“结果不完整”需要缩小范围后继续检索；术语存在歧义时先明确含义。资料摘录只是查阅线索，未经审核不能冒充已核实知识。

未启用生成式模型时，仍能查阅结构化知识和原文。启用模型后也仅可使用本次授权证据，引用必须通过证据标识、逐字文本和字符区间校验。系统不能仅靠引文校验保证模型结论在业务上正确；实际使用仍需专家标注的岗位评测。

## 资料怎样进入服务

构建者使用“创建知识服务模板”，先看将建立的类型、字段和关系，再明确确认安装。升级和打开页面都不会自动接管原业务数据。

编辑者在资料库上传获准文件，在知识服务中登记明确的资料分组、修订名称、业务范围、主题及生效日期。登记资料修订会引用原文件和不可变解析快照，不复制一套原文文件。资料日期较新不会自动取得替代权威；替代关系需要明确登记，且不能跨资料分组和范围。

使用现有本体工作室准备知识条目或通过资料加工提交候选；人工对照出处接受候选后，才进入有依据知识。首期沿用本体候选审核能力，完整的业务发布/退回/更新影响任务属于后续知识运营阶段。

原文字符位置按保存的解析文本计算，采用 Unicode 字符数，emoji 算一个字符。解析器可能规范化标点，因此解析快照和上传原文件分别提供。重新解析或原始文件发生变化时，旧证据仍固定指向原快照；界面明确提示原文件与所引版本的差异。不推测不可靠页码。

## 管理员怎样授权

知识服务读入口使用独立页面权限 `knowledge_service`；岗位读者无需 `types` 工作室权限。还要授予相应模型读取权限，并确保资料按现有来源授权可读。未关联资料沿用资料库页面权限，关联资料沿用其授权模型规则；入口权限本身不会额外开放来源。

反馈处理还需功能位 `knowledge_review`，且处理人员必须能读取反馈关联的模型和来源。构建模板需要 `types`、`model_manage` 和 `relation_manage`；登记资料需要 `file_write` 及对应空间模型写权限。既有角色在升级时保持原权限，由管理员明确授权新增入口。

条目、术语、原文、运行记录、反馈和关联信息每次读取都重新校验当前权限。完整导入对象要求全部已记录来源可读；混合来源对象可能整体隐藏。来源被撤回后，不用历史缓存继续返回正文。

## 检索边界与效果评价

中文检索使用字符规范化、受控术语别名和确定性关键词匹配；配置可用且用户有 AI 权限时，在已授权、适用且有审核依据的候选内进行有界向量召回和重排，失败时保留关键词检索。可选生成式模型仅在获准证据上组织答复。首期没有声称完成全局 GraphRAG、自动社区摘要或 RDF/OWL/SHACL 标准符合性。

查询运行固定原始入选结果、顺序和知识版本，回读前重新验证完整授权依赖。冲突的额外依据单独标注，参与排名但未命中的候选不冒充查询结果，也不能作为本次查询的反馈条目。

单次最多返回 50 项，关系最多两跳，明确记录对象、事实及资料扫描预算。可选生成答复输出上限为 1200 token，不自动扩大重试，并记录服务商返回的实际用量；其他已有 AI 功能保留原配置。预算耗尽提示结果不完整；不同适用范围不自动判为冲突。来源权限变化后重新查阅，不能把旧运行正文当作永久授权副本。

自动化验收使用合成中文资料、受控模型响应、临时数据库和独立备份副本。实际岗位效果须另用获准资料、专家答案和权限矩阵评价正确性、引文正确性、召回、拒答、冲突识别、P50/P95、耗时与 token 预算。本次自动化不向外部模型发送业务资料。

## 发布、验证与恢复

状态：第一期实现及验收中，正式运行结果以部署 manifest 为准。当前稳定服务已部署本体基座 1.11.0。

部署使用经过副本验收的版本镜像，保留原生产数据库、文件、配置和绝对挂载；先做两块磁盘的一致性备份并验证 SHA256，再切换镜像。正式服务只进行健康和授权只读核验，不创建测试账户、不运行清理测试。

出现新写入后不能把“切回旧镜像”当作数据回滚。恢复前停止写入并保存现状，明确逆迁移或补偿导出；不得直接丢弃新表、新知识、反馈或用验收副本覆盖正式数据。原 main 分支保持原状态，实施在 `codex/dynamic-ontology` 隔离工作区，尚未推送或合并。

## 最初会话协议报错的定位边界

`function_call_output requires call_id on HTTP requests; continuation via previous_response_id is only supported on Responses WebSocket v2` 表明当时接入的服务或适配器拒绝了工具结果关联和续接方式。应按该服务实际支持的协议，将工具结果关联到原始 `call_id`，并使用它支持的 HTTP 完整上下文或 WebSocket 续接方式；这条服务端限制不能泛化成所有 Responses API 的行为。

本项目当前模型服务按完整 endpoint 发送 Chat Completions 消息，工具结果使用 `role: tool` 与 `tool_call_id`；项目代码未发送 `function_call_output` 或 `previous_response_id`。本次本机接口及受控模型测试未复现原 session 报错，也未据此改动无证据关联的传输层。真实提供商和原会话适配器仍需分别实测，不能把本体或知识服务升级视为已经修复该外部协议问题。
