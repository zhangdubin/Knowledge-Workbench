# 从 Palantir 本体机制到中文知识服务

日期：2026-11-22。本报告以 1.11.0 本体基座为对照基线。用户已明确首批场景为知识服务，并批准按推荐设计实施第一期；中文知识服务第一期已完成副本验收并于本机部署 1.12.0；真实岗位效果仍需获准资料和专家评测。实际交付状态见 [知识服务运行说明](../knowledge-service-operations.md)。

## 结论与工作入口

建议推进以岗位工作为入口的中文知识服务：查到当前适用的资料和知识，打开精确出处，对分歧提出复核，把已确认的经验沉淀并跟踪更新。本体工作室由构建者维护；普通使用者进入知识服务工作区，专家进入待审和更新影响工作区。

Palantir 官方概览把 Ontology 定义为数字资产之上的组织操作层，包含对象、属性、关系，以及操作、函数、动态安全。应用参考又区分探索工具、单对象视图和面向具体工作流的应用。适配重点是把知识对象、证据、版本、授权和业务动作连接到日常任务。

- 普通用户：按中文问题、文号、术语和业务范围查资料，查看结论、适用期和出处，提交疑问。
- 知识编辑者：整理资料及候选，维护术语和知识条目，提交专家审核。
- 专家审核者：对照原文、处理冲突、批准发布或给出退回理由。
- 本体构建者：维护类型、共享约定、规则和能力接口，承担模式演进。

首批可覆盖制度流程咨询、保障资料查阅、培训参考和项目交付知识复用。具体内容以用户有权使用的资料和岗位要求为准。

## 逐项调研覆盖

原概览页的展开导航提供 327 个文档入口：325 篇中文功能/操作文章、文档首页和 API 索引。已核对这 325 篇的标题、小节和导语，并精读核心功能；另取得 7 篇英文核心文章核对术语。索引类入口没有被当成独立产品功能，API 索引下的所有接口端点未逐个调用。中文原站标注为机器翻译，功能成熟度和支持范围以对应文档为准。

交付材料：

- [334 行入口清单](palantir-feature-catalog.csv)：原目录 327 项及 7 项英文核对，每项标注能力族、阶段和知识服务用途。
- [32 项底座能力对照](palantir-foundation-capabilities.md)：对象、属性、值类型、接口、操作、函数、存储、迁移及权限。
- [应用能力对照](palantir-application-capabilities.md)：探索、对象视图、AI 逻辑与评估、监视、规则、图谱、流程、地图、调度。
- [来源目录快照](palantir-source-index.json)：标题、小节、官方地址和读取状态。

这些材料归并重复的创建、编辑、权限和入门教程，形成可实施能力清单。尚未逐步验证商业产品中的操作流程。当前工作依据公开文档设计本地能力；商业平台直连按实际授权和接口条件另行设计。

## 功能适配主线

| 官方能力族 | 知识服务中的含义 | 1.11.0 基础 | 适配方向 |
| --- | --- | --- | --- |
| 对象、属性和关系 | 资料修订、条款、术语、知识条目、引用和替代关系 | 稳定身份、版本发布、字段校验和兼容投影 | 提供中文知识服务模板和业务目录 |
| 共享属性、值类型、结构体、接口 | 统一“可引用、可审核、具有适用期”的契约 | 尚无通用共享属性/接口引擎 | 按实际重复模型逐步建立，先统一契约 |
| 操作类型及提交条件 | 提交复核、批准发布、退回、替代、撤回、处理反馈 | 持久化计划、版本检查、审核和审计 | 建立带角色和状态条件的知识业务操作 |
| 函数与能力 | 查询适用资料、对照证据、查影响、提出修改 | 四项内置类型化描述符与受限查询 | 版本化能力及输入输出合同，按岗位授权 |
| Object Explorer | 中文搜索、筛选、转向关联对象和比较集合 | 文档检索及受限对象/事实查询 | 文号、简称、术语、时点、范围和资料版本筛选 |
| Object Views | 一个知识对象的完整工作上下文 | 属性、双向关系、事实、证据和时间线 | 形成面向业务用户的知识详情和资料详情 |
| Workshop / Carbon | 为具体岗位组合信息与行动 | 现有应用工作区与五项主导航 | 知识服务应用、专家待审入口、更新影响入口 |
| AIP Logic 与评估 | 可重放的检索、引用回答、复核和模型质量评估 | 加工任务、助手运行记录和自动化回归 | 建立中文评测集，记录模型、提示和引用版本 |
| 监视、规则、流程分析 | 资料更新后生成复核任务，解释发布规则 | 候选、审核、变更计划与历史 | 先完成站内更新影响和反馈闭环，再评估通用编排 |
| 图谱、事件、时间序列 | 追踪引用、替代、适用和修订事件 | 已接受可见关系、两跳查询、有效期 | 先交付证据路径和修订时间线，按数据条件扩展 |
| 地图、调度、场景模型 | 需有地理、资源或预测模型的专项应用 | 未实现对应通用引擎 | 保留扩展边界，有明确场景和可靠输入后立项 |
| 治理、索引、存储与交付 | 跨入口一致授权、可重建索引、可靠升级 | 新增表、来源继承、CAS、幂等、备份与镜像 | 继续以实际数据规模和业务验收演进 |

Object Monitors 官方页面已指向 Automate，历史 Taurus 和旧对象存储内容作为迁移参考；后续设计采用可重放事件和明确状态，避免把历史工具直接列为建设目标。

## 相关先进技术如何融合

| 技术 | 采用的机制 | 本项目适配与验收 |
| --- | --- | --- |
| [W3C SKOS](https://www.w3.org/TR/skos-reference/) | 概念、首选词、别名、上下位、相关及跨词表映射 | 中文首选词和规范文号优先，英文缩写作为别名；同词异义按业务范围区分。扩展 RDF 导出时再验证标准符合性 |
| [W3C SHACL](https://www.w3.org/TR/shacl/) | 用形状约束验证数据并返回结构化问题 | 借鉴约束和校验报告思想，复用统一写入校验；现有 JSON 校验不能直接宣称完整 SHACL 实现 |
| [W3C PROV-O](https://www.w3.org/TR/prov-o/) | 资料实体、加工活动、责任主体及派生关系 | 将来源快照、加工任务、审核、发布和派生条目串联；保持原文、抽取结论与人工决定的区别 |
| [Microsoft GraphRAG](https://microsoft.github.io/graphrag/) | 实体与关系检索、社区层次、局部和全局查询 | 先用授权域内的混合检索和已核验关系路径；全局社区摘要在中文评测证明收益后引入，并绑定权限与版本 |
| [OpenLineage](https://openlineage.io/docs/) | dataset、job、run 及可扩展执行元数据 | 以现有摄取和运行记录建立内部血缘，再提供可互操作事件；当前不声称已接入其全部采集器 |

图检索、关键词检索和向量检索各承担适合的问题。精确文号、条款和版本由结构化条件控制；语义表达差异由混合检索与重排改善；跨资料关联由已接受且可见的关系辅助。生成答案只引用本次授权检索集合内的证据。原文不足、存在冲突或预算耗尽分别返回明确状态。

## 三种推进方式

| 方式 | 价值与代价 | 建议 |
| --- | --- | --- |
| 增量本体基座＋知识服务应用 | 复用现有权威存储、权限、证据、版本和操作；逐步补上业务入口与知识生命周期 | 推荐，先交付一个岗位可用的闭环 |
| 图标准与通用本体平台优先 | 提升跨系统语义互操作，需要新增存储适配、查询、权限和迁移验收 | 机构间交换需求明确后评估 |
| 文档问答应用优先 | 可快速验证检索与问答，后续仍需补齐对象、规则、专家审核和版本约束 | 可作为检索基线，与推荐方案的效果比较 |

## 建议分期

1. **中文知识服务应用**：普通用户入口、授权范围和时点筛选、术语别名、现行资料/历史资料、带出处答复与问题反馈。使用现有专家审核后的知识；模型未启用时仍能搜索和查看证据。
2. **知识运营闭环**：专家待审、固定业务动作、资料修订链、冲突处置、更新影响与待复核任务。
3. **可复用本体能力**：共享属性、值类型、接口、保存的对象集、规则配置和血缘交换。
4. **按场景深化**：较大规模 GraphRAG、流程分析、空间展示、通用调度和具备有效模型的场景分析。

第一期设计见 [中文知识服务应用设计提案](../superpowers/specs/2026-11-22-knowledge-service-foundation-design.md)。先用实际岗位问题、两类角色和一组授权资料验收，再决定下一期范围。
