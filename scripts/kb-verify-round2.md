## 二、六件事分别钉在哪个断言上

### 1. 长笔记不溢出编辑框
- 量的是**几何关系**，不是某个 class 是否存在：
  \`textarea.getBoundingClientRect().bottom <= .composer-body.getBoundingClientRect().bottom\`
- 高亮层与文字框高度差 ≤ 1px（双链高亮不错位）
- \`scrollHeight > clientHeight\` 且能滚到底（内容没被切掉）
- 编辑区高度 ≤ 可视区 - 120（不是写死的 620px 魔数）
- 两种模式都过：列表页内联新建（quick）、详情页整页编辑（full，由
  \`scripts/kb-verify-note-editor.cjs\` 覆盖）

### 2. 笔记加关联业务记录
- 数据是脚本自己造的：一条业务记录用接口挂上（\`POST /api/knowledge/link\`），
  另一条**留给页面上点**（\`.nd-link-candidate\`）—— 走的是用户真实路径。
- 关键断言是「**加完立刻显示**」：点候选之前记录列表条数 → 点 → 再数，
  不刷新页面（\`page.reload\` 一次都没有）条数必须 +1。
- 业务记录必须造在「有文本字段」的模型上：记录的检索文本（search_text）是
  模型各字段值的拼接，文本字段里填了关键字，对话框里才搜得到。

### 3. 双向链接
- 造两篇笔记：A 的正文里写 \`[[B的标题]]\`，再调 \`POST /api/notes/:id/sync-links\`。
- 断言「页面条数 == 接口条数」：\`GET /api/notes/:id/outgoing\` 与
  \`/backlinks\` 的条数要和页签里看到的条目数一样，
  并且条目标题对得上（避免「数量对、其实是另一篇」）。

### 4. 关联图谱的「笔记 ↔ 数据中心记录」
- API 侧（硬证据）：\`/api/graph/global\` 里笔记节点在（\`type_name=笔记\`），
  \`relation=关联知识\` 的边在，且这条边连的就是那条业务记录；
  \`/api/graph/notes\` 同样。
- 页面侧：图例里有「笔记」这一类节点、边图例里有「关联关系」
  （\`关联知识\` 属于这一类；具体是哪条关系只有接口说得清，画布上读不出来）。

### 5. DNA 文件在证据链
- DOM 断言（画布是 canvas 画的，但标题层是 HTML）：
  \`.dg-lbl-document\` 全部带 \`r\`（证据链），一个 \`.dg-lbl-document.l\` 都不能有；
  知识链那边是 \`.dg-lbl-gene.l\`。

### 6. 打印
- 六个页面：知识库 / 笔记详情 / 数据中心 / 记录 / 关联图谱 / 知识图谱。
- 打印按钮用 \`[data-print-trigger]\` 找；正文用 \`[data-print-root]\` 认；
  打印页眉用 \`[data-print-only]\` 认（屏幕上不显示、纸上要出现）。
- \`page.emulateMediaType('print')\` 之后量：侧边导航 display:none、
  正文可见且有字、正文区可见、打印页眉可见。

## 三、跑之前的注意事项

- 脚本会往库里造带时间戳的数据（\`验收记录一-20261102-213456\` 这种），
  跑完自动软删除（进回收站，可恢复）。别人的数据一条不碰。
- 前端要是没重建镜像，1/2/3/6 这几条会红 —— 那是「前端没上新代码」，
  不是功能坏了。重跑前先 \`docker compose build frontend && docker compose up -d frontend\`。
- 脚本不静默跳过：任何一条断言没过都会打印「期望什么 / 实际什么」，
  并以非 0 退出码结束。
